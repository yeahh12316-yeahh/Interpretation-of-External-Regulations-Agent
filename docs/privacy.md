# 隐私与数据流说明

## 核心边界

平台没有业务后端、用户数据库、云端文件存储或共享模型密钥。监管材料在浏览器中解析；只有用户明确发起模型分析时，相关文本才会从浏览器发送到用户自行选择的第三方 HTTPS 模型接口。因此，“数据不出浏览器”仅指平台不收集项目数据，不代表第三方模型调用不发生数据传输。

用户应在上传或发送前确认自己有权处理材料，并评估所选模型服务商的合同、地域、留存、训练和安全条款。本产品不替代机构自身的数据分类、跨境、保密和供应商审批。

## 浏览器保存范围

| 数据                                             | 默认位置                | 保存条件                                                                          |
| ------------------------------------------------ | ----------------------- | --------------------------------------------------------------------------------- |
| API Key                                          | 内存或 `sessionStorage` | 仅当前浏览器会话；不进入 IndexedDB、localStorage、URL、日志、备份、报告或构建产物 |
| API Base URL、模型名称                           | 内存；可选 IndexedDB    | 只有用户勾选“记住接口设置”才持久化；不与 API Key 一起保存                         |
| 解析文本、分析结果、证据锚点、复核记录、报告状态 | IndexedDB               | 用于刷新恢复与项目管理                                                            |
| 原始上传文件                                     | 当前内存                | 默认不长期保存；只有用户显式选择保存原文件时才可进入 IndexedDB                    |
| 项目 JSON 备份                                   | 用户主动下载            | allow-list 导出，永不包含 API Key                                                 |
| DOCX/PDF 报告                                    | 用户主动下载            | 只包含报告内容与证据/修订信息，不包含模型凭证或接口地址                           |

`sessionStorage` 在页面刷新后仍可能保留，关闭标签页或浏览器会话后清除；这符合当前会话凭证语义，但用户仍应在共享设备上主动清除数据并关闭会话。

## 第三方模型数据流

1. 用户分别上传监管原文和可选官方解读；
2. 浏览器本地解析并建立来源锚点；
3. 首次发送前，界面显示第三方模型数据流告知；
4. 用户确认后，浏览器把所需文本、结构化提示和 schema 直接发送给用户配置的服务商；
5. 响应在浏览器中校验、保存和复核；GitHub Pages 不提供代理，Vercel 仅按固定 Nova 端点提供受限转发，不提供共享凭证。

GitHub Pages 等纯静态构建要求服务商支持浏览器 CORS；Vercel 构建可使用同源的受限 `/api/model-proxy`，仅转发到固定 Nova 端点，不提供任意网址代理。API Key 不放入 URL、请求体或构建产物，代理代码不写日志或持久化密钥；仍应按托管平台的运行时日志和访问元数据政策进行部署评估。连接失败会在 UI 中区分鉴权、模型不存在、限流、超时、网络和 schema 错误。

## 静态托管与日志

公开静态站点向任何互联网访问者提供同一套代码和静态资产。托管平台可能按其政策记录 IP、User-Agent、请求路径等访问元数据；应用不会把监管正文、项目数据、模型地址或 API Key 编码到 URL。GitHub Pages 构建的模型请求直接到用户指定服务商；Vercel 构建启用代理时，模型请求会经过用户部署的 Vercel Function，但代理不保存或打印 API Key。

## 发布与导出防泄漏

- CI 不接受或注入共享模型凭证，GitHub workflow 权限固定为 `contents: read`；
- GitHub Actions 均固定到上游已核验的完整 commit SHA，checkout 禁止持久化凭证；
- 构建后递归扫描 `dist/` 的文本和二进制字节，缺目录、符号链接、单文件/总量越界、嵌套上传记录、压缩模型响应或凭证模式均失败；Vercel build command 本身也串联该扫描；
- scanner 有界展开 gzip/Brotli 静态文本与 JSON，并检查 UTF-8/带 BOM 的 UTF-16LE；ZIP/RAR/7z/TAR/XZ/BZip2/CAB 等未支持容器直接 fail-closed。唯一不展开的 gzip 是固定路径下的版本化 Tesseract `*.traineddata.gz` 公共运行时资产，它仍受锁文件与原始字节扫描约束；
- CSP 禁止 framing/object/base 注入，worker 仅允许同源或 blob，字体/图片限定为业务所需来源；`connect-src 'self' https:` 是支持用户任意 HTTPS BYOK 服务商的必要边界，不表示平台替用户信任任意服务商；
- source/dist/artifacts 扫描覆盖 DOCX ZIP 内容、PDF 原始字节与抽取文本；
- 生产冒烟只使用合成材料、合成会话凭证和浏览器 route 拦截，不调用真实模型账户；
- 正式 Deloitte 标识只有在取得授权资产和用途授权后才能进入产品，当前构建不包含标识图片。

浏览器端哈希用于一致性与修改检测，不是服务器签名或真实性认证。用户仍需核对监管文件来源、版本和效力状态。

## 用户控制

用户可在项目管理中按项目删除或清空本地数据，敏感删除操作有二次确认；可以导出经过净化的 JSON 备份，并在导入时接受版本与 schema 校验。共享设备使用完毕后，应清除项目、接口偏好和会话凭证。
